# Frontend context

This is the Next.js 16 (App Router) + React 19 + TypeScript browser application, styled with HeroUI v3 on Tailwind CSS 4 with Tabler icons, within the parent EduHub repository. Follow the workspace [context](../AI_CONTEXT.md) and [workflow](../AGENTS.md).

Routes live in `src/app/`: `(auth)` holds `/login`, `/register`, `/two-factor`, `/forgot-password` and `/reset-password` (no site header/footer), `(site)` holds `/home`, the informational pages, `/courses/[id]` (lesson player, `?lesson=<id>`), `/courses/create` and `/courses/[id]/edit` (both `components/CourseBuilder`, logic in `utils/courseForm.ts`) and `/settings` (two-factor on/off); `/` and unknown URLs redirect. Pages that read the session or theme are client components. `src/api/axios.config.ts` builds requests to `${NEXT_PUBLIC_API_URL}/api` (default `http://localhost:8000/api`); `src/api/courses.api.ts` contains course calls. Auth is Better Auth: server config in `src/lib/auth-options.ts` (instance in `src/lib/auth.ts`, handler at `/api/auth/*`, tables migrated into the Postgres `auth` schema on server start by `src/instrumentation.ts`), client in `src/lib/auth-client.ts` (`authClient.useSession()` for UI state). The session is an HttpOnly cookie; API calls carry a short-lived JWT from `get-session`'s `set-auth-jwt` header, cached by `src/utils/tokenCache.ts`. Email/password accounts must confirm their address before they get a session (`requireEmailVerification`); mail goes through `src/lib/mailer.ts` (SMTP; Mailpit in Compose). Two-factor is Better Auth's `twoFactor` plugin. There are no roles. `src/proxy.ts` sets the per-request nonce Content Security Policy (inline scripts need `nonce`); quizzes on the course page are graded by `coursesApi.checkQuiz`; builder drafts autosave via `src/api/drafts.api.ts`. Do not log tokens; emailed links reach the log only in the dev fallback without SMTP. Course creation can send JSON or multipart form data with images.

Use existing npm scripts and read [TESTING.md](TESTING.md) for commands and browser evidence. Browser tests live in `e2e/` (Playwright, `npm run test:e2e` against a running Compose stack; mail is read from Mailpit) and cover sign-up, confirmation, forgot password, building a course and taking it as a guest. `node_modules/`, `dist/`, and `.tmp-tests/` are generated.
